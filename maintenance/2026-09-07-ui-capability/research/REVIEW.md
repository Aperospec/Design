# design-craft UI 增补独立审核

日期：2026-09-07。只读范围：候选 SKILL.md 及三个 interface-*.md。依据为本轮已读的一手来源；未编辑 Skill 或原型。以下反例是对指令会引导什么交付的文本推演，未实际制作海报或数据表，也不等同用户测试。

结论：主要方法与来源一致，已覆盖上轮提出的实质 UI 缺口；无项目或平台默认污染。建议将一处流程表述改为条件性。共五项如下。

1. **方法匹配与缺口覆盖：通过，有一个可选补强。** 用户目标与对象关系对应 MIT；动作后的状态、结果、控制与恢复对应 Nielsen；复用及使用情境对应 GOV.UK；信息语义、键盘、焦点、反馈与局部验证边界对应 WCAG；真实参与者与模型走查的区分对应 think-aloud 的证据限制。处理接收/忙碌/成功、不确定响应下重试、输入保留、只读与不可用的区别、组件组合验证等均落到了实际判断，已超出纯静态视觉检查。MIT 的“典型数量与变化范围”在来源表中明确，执行正文第 9 行主要写对象关系、第 46 行只写“数量增加”；若要补强列表/表格能力，可在结构段增加“只有数量会改变组织或操作时，确认典型数量与可能范围”。不必要求每个界面都建立容量模型。ARIA APG 与两篇 Understanding 不在我前轮实际阅读集合中，本审核未独立复核这些补充链接的全文。

2. **项目、平台与审批污染：通过。** 主入口第 14、20、43、49 行及 interface-validation.md 第 15 行分别保护既定范围、局部修改、交付、项目参数和平台规范边界。正文没有把 Apple 安全区、Liquid Glass、某组设备断点、GOV.UK 品牌样式或固定 WCAG 数值设成所有项目默认；也没有新增 ECD、部门报表、签字或用户研究审批。组件库从真实重复问题提取，未规定先建立完整系统。

3. **建议小修：线性流程中的中间步骤应可省略。** interface-design.md 第 11 行“为关键任务画最小流程：入口 → 选择或输入 → 系统处理 → 结果与后续”仍像必须经过的阶段；第 13 行“先用线框或低成本原型检验结构，再精修视觉”也容易覆盖已解决结构的局部工作。虽有顶部按需选择及主入口保护，局部措辞可以更一致。建议表达为：“结构或路径尚未明确时，用最小流程或线框检验；流程只保留任务实际包含的查找、理解、输入、处理和结果环节。已有结构有效时直接修改受影响部分。”这是一处条件化修订，不必新增章节或报告。

4. **差异用途：只改展览海报标题层级——应直接交修改后的海报，推演通过。** 输入已锁定文字和风格；只在现有字体、色彩与图像关系中调整标题大小、位置、间距等必要项，打开实际海报并按约定观看尺度核对层级、断行和文字完整性。交付修改结果及任务需要的源件，简短说明变化和检查范围。主入口“单张修订可以直接完成”“只获准排版时不要静默改字”足以保护此用途；应选构图、字体和视觉评判，不读入任务流程、控件状态、组件库、键盘验证或参与者研究。没有发现新增 UI 方法会强迫该任务走这些步骤。

5. **差异用途：只读二维数据表——应保留有意义的行列关系，推演通过但受第 3 项措辞影响。** 以查找单元格、跨行/列比较及理解表头/单位为任务，交付可读表格界面或本次所需的设计/原型；数据、表头关系和阅读顺序准确，窄空间可用适当局部滚动，外围标题和必要说明可重排。若环境允许，应检查键盘/辅助技术访问表头及数据；若只交静态图，则说明语义和操作尚未验证。无需为只读数据制造输入、保存、取消、撤销或编辑状态；排序筛选、异步加载等仅在原任务包含时设计。interface-validation.md 第 11 行明确二维空间例外且禁止强制单列，因此不存在把所有表格拆成卡片或单列的要求。
