# 字体、中英混排研究与改动候选

研究日期：2026-09-06。研究者：本轮独立字体研究代理。范围：实际阅读当前字体参考文件、任务 brief、项目 AGENTS.md；用 research-craft 建立证据，用 writing-craft 校核这份笔记。未修改 Skill，也未执行字体渲染实验。以下测试是供主任务执行的设计，不是结果。

## 当前方法的缺口

现有参考已包含语义断行、真实字样比较、地区字形、后备字体、等宽数字、光学校正与实际导出。应保留这些拆分后补回的内容。真正缺口较窄：

- 已要求检查字体，但没有清楚区分字体家族宣传、实际装载文件、软件请求值与最终使用字形；所以“设置正确”仍可能被误当成“渲染正确”。
- 已要求遵守中文禁则，却没有交代断行、标点空白与段落调整相互影响；遇到局部行尾问题，执行者可能用整段挤字作为万能修补。
- 已区分数字字宽，但未区分数字形态，未说明“选择等宽数字”本身不能完成比较列的对齐。

这三项属于方法操作不够明确的候选。若操作者明知现有要求却未检查，属于执行错误；如果指定模板或指定字体本来就在限制选择，属于项目约束，不能借这轮升级废除模板或强制重选字体。

## 实际读取的一手依据

以下只保留短摘要与定位，不复制整篇资料。每个网页的实际阅读状态单独记录，检索摘要不算正文。

### S1 — W3C《中文排版需求》

- URL：[2026-09-01 固定版本](https://www.w3.org/TR/2026/DNOTE-clreq-20260901/)，实际读取入口为 [最新发布版](https://www.w3.org/TR/clreq/)。
- 状态：正文页头为 **Group Note Draft，01 September 2026**。是进行中的排版需求文档，未获 W3C 会员认可；不能称作最终标准。检索封面曾返回 8 月版本，故以实际正文为准。
- 读到：§1.2、§1.4.2、§6.1.1、§6.2.2.1–3、§6.2.3、§6.3.2–3、§6.4。条文与中英文正文均实际展开阅读；不声称通读全篇。
- 与本次有关的摘要：地区排版规则不能只凭繁简判断；标点宽度会改变断行；行内调整区分可调空间；中西边界的留白有行端及标点邻接例外；西文词内部不应被中文均排拆散。
- 采用边界：只给中文及中文内混排提供按条件处理的依据，不把书籍两端对齐推广到所有短标题、界面、单图或纯西文正文。

### S2 — OpenType：光学字号轴

- URL：[Registered Design-Variation Axis Tag: opsz](https://learn.microsoft.com/en-us/typography/opentype/spec/dvaraxistag_opsz)。
- 状态：OpenType 1.9.1 文档，页面最后更新 **2024-05-29**。
- 读到：Axis definition 与 Additional information 全部正文。
- 摘要：光学字号改变字形设计，并非把轮廓等比缩放；应考虑实际观看大小、距离及平台缩放。轴可存在于可变字体，也可描述静态光学字号家族。
- 采用边界：字体确有该能力才值得验证；不得把某个光学字号、缩放比例或视距写成默认值，也不能说所有字体都需要可变轴。

### S3 — W3C CSS Fonts 4

- URL：[2026-08-31 固定版本](https://www.w3.org/TR/2026/WD-css-fonts-4-20260831/)，实际阅读入口 [CSS Fonts Module Level 4](https://www.w3.org/TR/css-fonts-4/)。
- 状态：**Working Draft，31 August 2026**。搜索返回较旧日期，实际正文页头更新。是工作草案；不以有规范文本证明所有环境已实现。
- 读到：§2.8 Controlling synthetic faces、§5 Font Matching Algorithm、§8.1 Optical sizing control 的相关正文及示例。
- 摘要：缺少合适字形时可能产生合成粗斜；字形匹配按文本运行而非仅凭家族名字；光学字号自动行为依赖字体支持及渲染环境。
- 采用边界：从 Web 机制提炼“核验实际字形”的动作。不能向所有平面软件写死 CSS 指令，也不把关闭合成设置当作已经取得真实粗体。

### S4 — 字体制作者 Type Project：数字字宽与形态

- [Tabular Figures and Proportional Figures](https://staffblog.typeproject.com/en/3381)，**2024-02-19**，全文读取。
- [Lining Numbers and Old Style Numbers](https://staffblog.typeproject.com/en/3402)，**2024-03-11**，全文读取。
- 摘要：前者以自身字体解释 `tnum` / `pnum` 及默认值命名可能引起的混淆；后者明确齐线/旧式与等宽/比例是两个维度，可组成四类。字体可能只提供其中部分。
- 采用边界：这是字体制作者对实际特性的说明；其日文字体默认值不推成所有中文、拉丁字体的默认值。

### S5 — OpenType：数字特性定义

- URL：[Registered Features, p–t](https://learn.microsoft.com/en-us/typography/opentype/spec/features_pt#tag-tnum)。
- 状态：OpenType 1.9.1 文档，最后更新 **2024-05-31**。
- 读到：`pnum` 与 `tnum` 的 Function、Example、implementation、interaction。
- 摘要：两者在相应字体中切换比例或统一前进宽度，可以作用于齐线或旧式数字；默认是否等宽不作绝对保证。这些特性不用于本来全字等宽的设计。
- 采用边界：特性定义是功能依据，不是工具支持证据；实际文件、排版应用及导出仍须验证。

### S6 — Elliot Jay Stocks：选字检查表

- URL：[作者维护的检查表](https://github.com/elliotjaystocks/choosing-type-checklist/blob/main/README.md)。
- 状态：作者公开仓库 `main`，读取时为 25 行 README；本次页面没有取得可靠发布日期或固定提交，因此不编造时间。
- 读到：全文；页面直接链接 Google Fonts Knowledge 原文。
- 摘要：功能要存在于实际使用的文件中，兼顾用途、语言与字形设计。能力丰富只是候选优势，不代表每次都需要全部字重、字宽和光学字号。
- 访问限制：Google Fonts Knowledge 的两篇页面（[checklist](https://fonts.google.com/knowledge/choosing_type/a_checklist_for_choosing_type)、[optical sizes](https://fonts.google.com/knowledge/choosing_type/choosing_typefaces_that_have_optical_sizes)）本次工具仅读到标题、正文 0 行。没有把它们算作已读证据。

### S7 — Google Design：有用但不可整套移植的入门建议

- URL：[How to Choose a Web Font](https://design.google/library/choosing-web-fonts-beginners-guide)。
- 状态：Google 官方入门文章；本次所读页面无可靠发布日期。
- 读到：项目范围、字号、语言、功能及字体配对各节。
- 摘要：主张按实际角色、语言与字体功能进行比较，也承认短期作品可只需一个字重。
- 不采纳：按段落数量决定衬线/无衬线、按固定字号区间配字体类别，证据不足以作为通用规则。该文把旧式与等宽并列对照，容易混淆两个维度；本次以 S4、S5 的明确功能定义为准。这是来源比较发现，不是作品实验结论。

## 建议加入现有参考的少量机制

### M1 — 给选字证明加上“实际字体状态”

在同文、同角色、同观看条件的候选比较旁，记录实际文件或字形来源；只核对本任务用到的语言、字重和特性。若效果没有变化，先判断未启用、不支持、后备替换还是差异太小，不能只据菜单已勾选宣称成功。以 S2、S3、S6 为依据。

适用：字体候选、角色跨度或渲染路径会影响结果时。反例：已有指定字体且角色简单，不必另做大量选型；真实粗体不存在时，禁用伪粗可能让层级消失，需重新验证层级。

### M2 — 把局部排字故障落实到可调对象

先确定任务地区与排版体例；局部故障定位到标点空白、中西边界、词间或断行，再实测调整后的整段。不要把字形横向缩放或整段 tracking 当作自动解法。地区规则、标点宽度与行端例外依据 S1，具体修复仍由作品判断。

适用：出现禁则、拥挤或过疏的中文/混排文本。反例：有意疏排短题可以保留；纯英文段落不能套中文挤压顺序；为符合禁则造成明显过疏时，需考虑栏宽或版式，而非无限挤推。

### M3 — 分开判断数字功能与比较结构

数字字宽与数字形态分别选择，确认实际特性可用。比较任务还需核对数字位数、小数点、符号及单位的对齐关系；这一步是从本项目“比较数值”任务需求推导的设计操作，不能由 `tnum` 功能定义代替。以 S4、S5 为功能依据。

适用：表、列表、变化数值或正文中的数字。反例：叙述段落没有纵向比较需求，等宽未必更合适；数字小数位不同时，统一字宽不会自动对齐小数点。

## 交给主任务的可检视验证设计

以下字符串与数字是本维护项目的试验输入，不应写入底层 Skill、模板或默认脚本。每项同时保存原方案与修复方案，清楚标记作者自审，不能据此宣称读者实验。

| 候选 | 实际证明 | 可记录的数据/现象 | 应失败或不采用的反例 |
|---|---|---|---|
| M1 | 同一段真实中英字样，主字体可用/不可用两个状态；正文与大标题各看原尺寸 | 实际字形来源、缺字/替换、行数或溢出、真粗与合成粗的轮廓差异 | 已指定且可用的单一字重，不应强制再选字体 |
| M1 光学字号分支 | 用确有 `opsz` 的字体，同一小尺寸并排比较不同光学实例；大标题再比较 | 字面、开口、笔画与段落宽度差异；记录实际字体版本和轴值 | 无 `opsz` 字体应报告不适用，不“模拟”出支持；屏幕图不能证明印刷 |
| M2 | 同一窄栏混排文字，分别只改标点/边界与整段挤字；另做较宽栏 | 字符串完全一致；行首/行尾、连续标点、西文词及数字内部是否受损 | 疏排题字或纯英文段落不应被自动密排；窄栏无解时允许结构调整 |
| M3 | 比较 `111.1`、`888.88`、`−7.05`：比例、等宽、按小数位置安排三个状态；再做含年份的英文段落 | 数字前进宽度、关键位或小数点位置；符号与单位没有被省略 | `tnum` 单独不足以解决不等小数位；正文仍可使用比例/旧式数字 |
