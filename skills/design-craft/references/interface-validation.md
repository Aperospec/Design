# 界面验证与交付

按设计要支持的实际任务选择检查。草图评议、可交互原型检查、自动化检查、目标用户测试及上线使用证据分别记录；完成前一种不代表后一种。专业依据见 [界面方法依据](interface-method-basis.md)。

## 适配保持任务可完成

从内容和操作的空间需求确定布局约束：哪些固定、伸缩、换行、重排、折叠或局部滚动，以及变化后用户如何继续原任务。用出现拥挤、遮挡或顺序混乱的位置决定切换布局的条件，不默认套某组设备尺寸。

在目标环境检查宽窄空间、长内容和必要的语言变体；放大文字与缩小窗口分别检查。确认信息、动作和状态仍可访问，阅读与键盘顺序仍有意义。软键盘、固定栏或浮层出现时也要保留当前输入与关键动作。以重排和合理滚动处理内容，不将整张画面缩小当作适配完成。

地图、数据表或编辑画布等可能需要二维空间：保留完成任务所需关系，提供适合的局部滚动或替代呈现，并让外围说明、操作与焦点仍可访问。并非所有界面都应强制变成单列。

## 将无障碍落实到行为

先确定当前平台、支持范围和适用规范版本，把具体要求记入项目约定。规范中的阈值、例外和等级随其适用范围使用，不能将某平台参数推广为通用默认。Web 可查 WCAG 与 ARIA APG，原生界面使用对应平台的控件与无障碍指南。

对受影响流程检查：

- **可感知：** 文字、控件边界和状态在相关背景下可辨；含义有颜色以外的线索。图像、图标、字段及动作具有合适的名称或替代信息。
- **可操作：** 用目标输入方式完成真实任务；键盘可到达控件并按预期触发，焦点可见且不被遮挡。顺序符合阅读与操作逻辑；对话框能进入、退出，关闭后焦点回到合理位置。悬停专属内容与拖拽操作按需要提供其他可用方式。
- **可理解：** 标签、帮助和错误与具体输入关联；状态和结果清晰。设置变化不无故触发跳转或提交；用户有机会理解并纠正重要操作。
- **可被辅助技术识别：** 核对实际名称、角色、值、状态、分组与动态消息语义。优先采用具备相应行为的原生控件；仅添加 ARIA 属性不会自动补全键盘操作。重要动态反馈按紧急程度提供可感知方式，不让所有变化都反复打断。
- **适应个人需要：** 检查内容放大、必要的触达范围、运动偏好和时限。需要限时或短暂反馈时，说明依据并提供适用的调整、延长或持续可访问途径；运动传达变化时保留降低运动后的意义。

实际运行再核对辅助技术与浏览器/平台组合。自动扫描或查看语义树能发现部分问题，不能证明读屏体验或符合全部标准；无法执行的范围明确列出，不标为已通过。

## 用任务验证，不只看页面

从目标中选代表性的主要路径和影响较大的恢复路径，写清起始条件、用户要完成的结果以及可观察的成功条件。简报已明确的要求纳入检查；陌生用户能否理解则需要独立观察，不由设计者替答。

先让原型的关键控件和状态实际运转，用指针和必要的键盘操作走通流程；确认反馈、输入保留、返回、重试和状态一致性。用具有差异的内容或条件试用，例如长内容与窄空间、已有数据与空状态、只读展示与编辑操作。只审静态图时，只作静态范围判断。

需要验证可用性时，给参与者现实的任务目标和必要背景，不泄露界面路径；观察其发现入口、理解标签、判断结果和恢复错误的过程。记录完成情况、绕路、误操作、犹豫与干预；时间数据须保留任务和条件。不以“喜欢”或设计者说明替代任务表现，不从少量方便样本推出整个受众效果。

问题记录落到发生位置、可复现步骤、实际后果和受影响人群；根据任务阻断、损失与覆盖范围决定优先级。修改后复测受影响路径及相邻正常路径。模型走查有助于早期发现问题，目标用户观察用于验证真实理解；不可互相冒充。

比较方案时保持任务和关键条件可比，检查改善是否带来新损伤。一次前后试用仅说明该样本的表现，不足以证明 Skill 普遍优于旧版。达到本次成功条件且无明确未解决缺陷后结束，不因还能增加更多方法而无限扩测。

## 交给实现者的最小完整依据

按交付范围提供实际设计文件或原型，加上仅凭画面无法恢复的信息：

- 关键任务路径、业务条件来源、状态转换及失败后的恢复；
- 组件及变体的用途，复用来源、语义角色、输入与焦点行为；
- 布局约束、内容和语言边界、适配条件，以及准确文案与资产；
- 已执行的检查、存在的缺陷和未验证条件。

区分视觉定稿、可修改的设计关系与实现限制。模拟数据、等待或失败开关留在原型说明或演示区域，不能混成产品功能。开发返回冲突时先核对用户任务与设计约束，再修正有影响的部分。交付规格和可点击原型不等于已上线实现；实现完成后按影响核对实际视觉和行为。
